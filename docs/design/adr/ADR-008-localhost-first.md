# ADR-008：先に localhost で作って試し、OK が出てから exe にする
- 状態：承認 ／ 日付：2026-11-06 ／ 決定者：ユーザー
- 影響する ID：REQ-007, REQ-008, FR-001, FR-002, FR-007, FR-019, FR-020, API-001〜010, API-093〜094, NFR-010, NFR-011, NFR-014, ADR-001

## 状況
これまでの設計は最初から exe（Electron＋NSIS）を前提にしていた。機能や使い勝手が固まる前に配布の仕組みまで作ると、試して直すたびの手間が大きい。

## 決定
2段階に分ける。まず WSL の worker が `http://127.0.0.1:8787` で画面と API を出し、ブラウザで試す（localhost 段階）。利用者が OK を出してから Electron に包んで exe にする（exe 段階）。exe 段階の中身は ADR-001・ADR-007 のまま変えない。詳細は [12](../12_localhost_stage.md)。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 最初から exe | Windows での動きを早く確かめられる | 配布まわりを先に作るので、試し始めるのが遅い | ユーザーが不採用 |
| Windows で直接動かす | exe 版と同じ条件で試せる | Windows 側に開発環境が別に要る | ユーザーが WSL を選んだ（R-15 は exe 段階で確認） |
| Electron の開発モードで試す | IPC をそのまま使える | Electron の準備が先に要る | ブラウザで試すという要望に合わない |

## 影響
- 画面は `src/platform` の接続層だけを通して OS の機能を使う。worker は Electron に依存しない
- `window.llmParty` が使えないので、フォルダ選択はパス入力、HF トークンは API-094 で代える
- Windows 固有の動きの確認は exe 段階に回る（R-15）
- localhost 段階のデータは exe 版へ引き継がない
