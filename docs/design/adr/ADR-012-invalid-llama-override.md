# ADR-012：`LLM_PARTY_LLAMA_BIN` のパスが実在しなければ、警告して無視する
- 状態：承認・実装済み ／ 日付：2026-11-07 ／ 決定者：ユーザー（無視して続ける）＋ Claude 判断（警告の出し方）
- 影響する ID：FR-003, API-023, API-099, CP-313, D-74, R-19, ADR-011

## 状況
仮の値 `/path/to/llama-server` が保存済みの起動コマンドに残り、取得済みの本体があるのにモデルを読み込めない失敗が繰り返された。今の設計は起動時に警告だけを出し、読み込みで初めて `failed` にする。ADR-011 で手動指定は必須でなくなったのに、指定を1つ間違えると全機能が止まる。

## 決定
パスの形の指定が実在しないときは `failed` にしない。警告（CP-313）を出して指定を無視し、取得済み → 自動取得の順に進む。バックエンドは `LLM_PARTY_BACKEND` ではなく、ADR-011 の D3 で決める。

警告は起動時と読み込みのたびに確かめ、ターミナルと画面の帯に出す。画面は `engine` イベント（API-099）と API-023 の `warning` で受け取る。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 起動の時点で止める | 指定を黙って差し替えない | 仮の値が残っている間は毎回起動できない | 利用者が困る回数が減らない |
| 環境変数を廃止する | 再発の経路が消える | 自分でビルドした本体を試す手段がなくなる | 上書きの用途は残す |
| 失敗のまま文言だけ直す | 変更が最小 | 同じ操作で毎回失敗する | 今回の問題が解決しない |

## 影響
- 読み込みが止まらない代わりに、打ち間違いで別の本体が動くことがある（R-19）
- 何も取得していなければ、無効な指定のまま約 780MB の自動取得が始まる（ADR-011 の D1）
- 変えない場合：パスの形でない指定（`llama-server` など）は spawn に任せ、見つからなければ `failed`。実在する本体が動かないときも `failed`。指定を明示した以上、動かない原因は隠さない
- `LLM_PARTY_SD_BIN` は今回の対象外（ADR-011 の D6 と同じ）
