# ADR-015：音楽は専用の画面に一本化し、曲をスレッドから切り離す
- 状態：承認（2026-11-07）／ 決定者：ユーザー（専用画面・一本化・2列）＋ Claude 判断（データの移し方・API の形）
- 影響する ID：REQ-014, FR-023〜FR-027, SCR-010, PG-010, TBL-018, API-103, API-104, API-108〜114

## 状況
歌詞の下書きと手直しには、3 行の入力欄では狭い。曲はスレッドに紐づくので、スレッドを消すと記録も消え、チャットのプリセットがないと曲を作れない。

## 決定
左端のアイコン列に「音楽」を足し、一覧＋エディタの2列の画面（`#/music/:id?`）を作る。スレッドの入力欄から音楽モデルを外し、API-103・API-104 は廃止する。新しい曲は `thread_id = NULL` で保存する。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| スレッドにも入口を残す | 手軽さが残る | 生成の入口が2つになり、画面と処理が二重になる | ユーザーが一本化を選択 |
| 入力欄の上のパネルにする | 変更が中くらい | 一覧と作り直しの置き場がない | ユーザーが専用画面を選択 |
| 新しいアプリを別に作る | 音楽に特化できる | DL・レシピ・生成の枠を作り直す | ユーザーが local-chat への追加を選択 |

## 影響
- DB は v8。`tracks.thread_id` を NULL 可・`ON DELETE SET NULL` に替え、`bpm`・`keyscale`・`reasoning` を足す（テーブルの作り直し）
- 過去の曲はスレッドで再生でき、一覧にも出る。`MusicMessage` は残す。曲を消した後は CP-356 を出す
- スレッド用の `MusicOptions`・`musicMode` は要らなくなる
- 音楽モデルだけでプリセットがないと曲を作れない問題（[変更記録](../changes/2026-11-07-music-generation.md)の未決）は、音楽については解消する
