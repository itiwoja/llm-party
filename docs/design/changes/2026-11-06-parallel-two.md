# 変更記録：生成を同時に2本まで（2026-11-06）

> **3行で**：llama-server を `--parallel 2` にし、生成の枠を2本にする ／ 枠は「読み込みが同じ」生成どうしでだけ一緒に持つ（違う読み込みは読み直しを防ぐため待つ・BUSY） ／ `-c` は変えないので、1本あたりの文脈は半分になる

## 依頼と決定
| 項目 | 決定 | 根拠 |
|---|---|---|
| 対象 | LLM の生成（チャット・評価）を同時2本まで | ユーザー回答（「同時に送れるクエリを2件に」→ LLM 生成） |
| 文脈長 | `-c` は変えず、2本で分ける（1本あたり半分） | ユーザー回答（既定のまま）。VRAM を増やさないため |
| 読み込みが違う生成 | 枠を分けず、持っている枠が空くまで待つ（チャットの送信は BUSY） | 読み直しで動いている生成が止まるのを防ぐ（助言） |
| 同じスレッド・同じワークスペース | 1つだけ（D-36 のまま） | 書き込みの衝突を防ぐ |
| 画像生成 | チャットが動いていない間だけ（従来どおり） | VRAM を取り合わない（D-72） |

## 影響（既知）
- 1本あたりの文脈が半分になる。プリセットの文脈長を変えずに使うと、長い会話の要約が早く働き、要約しても入らない場合（CP-050）も早く出る。文脈を戻すには、プリセットの文脈長を2倍にする（`-c` は総量）。
- 評価（FR-016）の1ケースも同じ半分の文脈で流れる。評価の結果が変わる可能性があるので、比べる前に既存のランと条件を揃えること。

## 確かめ
- `npm test` 全件（330 件）、`npm run typecheck`、`npm run build` が通る
- 新しい試験：別スレッドは同時に2本、3本目は BUSY（`tests/chat.test.ts`）、同じスレッドは BUSY、読み込みが違う生成は BUSY で読み直さない
- 実際の llama-server（GPU）での同時2本の動きは未確認
