# 変更記録：VRAM推奨・RAM推奨と、GPU に載せる割合のバー（2026-11-07）

> **3行で**：HF の表の「目安メモリ」を容量・VRAM推奨・RAM推奨に分ける ／ 「GPU に載せる割合」のバーで表の値と絞り込みが変わる ／ プリセットに割合を保存し、読み込み時に `-ngl` へ渡す

## 依頼と決定
| 項目 | 決定 | 根拠 |
|---|---|---|
| 表の列 | 容量・VRAM推奨・RAM推奨 | ユーザーの依頼。1列では何の値か分からなかった |
| バーの役割 | 表の試算だけでなく、実際の読み込みにも効かせる | ユーザー回答 |
| 検索結果 | ファイル一覧と同じ列にそろえ、絞り込みも VRAM推奨・RAM推奨のそれぞれで判定する | ユーザー回答 |
| プリセットの既定 | 自動（`gpu_ratio` が NULL。今までの `-ngl auto` と同じ） | 既存のプリセットの動きを変えない |
| 計算の置き場 | `server/hf/memory.ts` を画面からも読む | バーを動かすたびに API を呼ばない。式を二重に持たない |

## 影響（既知）
- 割合が 100% だと RAM推奨は全行 4GB になるので、「RAM まで」の絞り込みは 4GB 以上ならほぼ何も外さない。GPU なしで探すときは割合を 0% にする。
- 明示の割合では llama-server の自動調整が効かないので、VRAM が足りないと読み込みに失敗する。自動のときは今までどおり。
- バーの探し直しは上限が入っているときだけ。開いているファイル一覧は閉じない。

## 実測（Qwen3.5-9B Q4_K_M 5.68GB、`-c 32768 --parallel 2`。block_count 32、全 33 層）
| `-ngl` | 載った層 | VRAM の増え | RSS |
|---|---|---|---|
| 0 | 0/33 | 309MiB | 6452MiB |
| 16 | 16/33 | 3581MiB | 3760MiB |
| all | 33/33 | 6221MiB | 1033MiB |

推奨の式（100% で VRAM 約 7.2GB）は実測よりやや多めに出る。`-ngl` を指定しても `-c` と層の数は変わらなかった。

## 数字（ユーザー確認済み）
- RAM の固定分 4GB、VRAM の固定分 1GB（GPU を使わないときは RAM へ）、バーの刻み 10%、HF のバーの初期値 100%。
