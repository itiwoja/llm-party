# 変更記録：入力欄で思考の強さを選ぶ（2026-11-07）

> **3行で**：プリセットの右に思考の選択欄を足す（対応するモデルだけ） ／ 対応はチャットテンプレートの変数で見分ける ／ 選んだ値はプリセットに保存する

## 依頼と決定
| 項目 | 決定 | 根拠 |
|---|---|---|
| エフォートの意味 | `reasoning_effort` があるモデルは段階、`enable_thinking` だけのモデルは ON/OFF | ユーザー回答。手元の Qwen3.5-9B のテンプレートには `enable_thinking` しかなく、段階だけだと欄が出ない |
| 段階と既定値 | 低・中・高。既定は中 | ユーザー回答 |
| 覚える単位 | プリセットごと | ユーザー回答。変更すると同じプリセットの全スレッドの次の送信に効く |
| 表示の語 | 「思考 低」「思考 オフ」など | プリセット編集の「思考モード」、会話の「思考」に合わせる |

モデルごとの選択肢：

| テンプレートの変数 | 選択肢 |
|---|---|
| `enable_thinking` だけ（Qwen3.5-9B） | オフ / オン |
| `reasoning_effort` だけ | 低 / 中 / 高（思考を切れないので `enable_thinking` は常に `true` で送る） |
| 両方 | オフ / 低 / 中 / 高 |
| どちらも無い・テンプレートが無い | 欄を出さない（これまでどおりプリセットの値を送る） |

## 影響（既知）
- 要約（FR-006）は従来どおり思考 OFF で、段階を送らない。
- 段階に対応するモデルは手元に無い。段階の実際の効き目（出力の変化）は未確認。

## 確かめ
- `npm test`、`npm run typecheck`、`npm run build` が通る
- 実際の llama-server（b12125）で、`chat_template_kwargs.reasoning_effort` が `/apply-template` のテンプレートへ届く（low / high。未指定は medium）。段階を書いた仮のテンプレートを使った
- DB の写しで、v4 からの移行と起動時の読み取りで Qwen3.5-9B が `enable_thinking` のみと判定される
- 画面（1280px, 960px）：Qwen3.5-9B はオフ / オン。対応フラグを立てた写しでオフ / 低 / 中 / 高が出て、選ぶと保存され、選んでいたプリセットが戻らない
