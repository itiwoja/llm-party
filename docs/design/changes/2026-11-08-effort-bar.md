# 変更記録：思考の段階をバーで選ぶ（2026-11-08）

> **3行で**：入力欄の段階のセレクトを、押すと開くカードのバーに替える ／ オンオフは脳のボタンのまま ／ 保存は指を離したときにする

## 依頼と決定
| 項目 | 決定 | 根拠 |
|---|---|---|
| 見た目 | Codex のバーに合わせ、段階の名前・↺・丸いつまみのバーをカードにまとめる | ユーザーの依頼（画像） |
| 置き場所 | 入力欄の「思考 中」を押すと上にカードが開く | ユーザー回答。入力欄の下の段は幅が狭く、名前と ↺ を置けない |
| オフの扱い | バーは低・中・高の3段で、オンオフは脳のボタンのまま。オフの間はバーを出さない | ユーザー回答 |
| 段の数 | 選択肢の数（3つ）。画像の5段にはしない | D-76 で低・中・高に決めている |
| 色 | 段階の名前は `--color-primary`、つまみは `--color-fg` | 画像の青と白はアプリの配色に置き換える。ライトではつまみが黒になる |
| 保存の時 | 指かキーを離したとき | 途中の段階を送らない。GPU のバーと同じ考え方 |
| 部品 | `@radix-ui/react-popover` を足す。バーは `input type="range"` | カードの開閉とフォーカスを任せる。メニューとダイアログは中に操作部品を置く形に合わない |
| 編集画面 | セレクトのまま | 依頼は入力欄のバーの見た目で、オフも同じ欄で選ぶ形が別 |

## 影響（既知）
- 段階を変えるのに1手増える（押して開く）。今の段階はボタンの文字で見える。
- 保存の中身は変えていない。同じ API-062 に同じ値を送る。

## 確かめ
- `npm test`、`npm run typecheck`、`npm run build` が通る
- 写しの DB に段階対応のモデルを入れた画面（1280px ダーク、960px ライト）：カードが入力欄の上に開き、つまみと目盛りの中心が合う
- クリック、外で離すドラッグ、矢印キー、↺ の4通りで、プリセットの `effort` が選んだ値になる。ドラッグの途中は保存されない
- 開くとバーにフォーカスが移り、Esc で閉じる。脳のボタンでオフにするとバーが消える。段階だけのモデルは脳のボタンなしでバーが出る
- 段階の実際の効き目（出力の変化）は、手元に対応モデルが無く未確認（D-76 と同じ）
