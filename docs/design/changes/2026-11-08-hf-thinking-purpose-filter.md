# 変更記録：HF 検索を思考と用途で絞れるようにする（2026-11-08）

> **3行で**：HF 検索に「エフォートあり」「思考あり」のスイッチと用途のセレクトを足す ／ 思考は HF が返すチャットテンプレートで DL 前に判定する ／ 用途は HF のタグで絞る

## 依頼と決定
| 項目 | 決定 | 根拠 |
|---|---|---|
| 絞る項目 | エフォートあり・思考あり・用途（日本語・コーディング・ロールプレイ） | ユーザー回答 |
| 外した項目 | ツールあり、画像入力 | ツールは GGUF の DL 上位 200 件のうち 182 件にあり、ほぼ絞れない（ユーザー回答）。画像入力はアプリが対応していない |
| 思考の判定 | `gguf.chat_template` を `thinkingSupport()`（D-76）で見る | DL 後のモデルと同じ判定にすると、絞って取ったモデルに段階の欄が必ず出る |
| 「思考あり」の意味 | `enable_thinking` か `reasoning_effort` がある | 段階だけのモデルも思考を操作できる。`<think>` を書くだけのテンプレートは、アプリから操作できないので入れない |
| 用途の判定 | HF のタグ。別名（`ja` と `japanese` など）はタグごとに検索して混ぜる | 実測で別名の両方に結果がある。HF の `filter` は重ねると AND になる |
| 画面 | スイッチは無検閲の並び、用途はセレクト1つ、結果に「思考」の列 | 用途の AND はほぼ空になるので1つだけ選ぶ |
| 取得の上限 | エフォート・思考・VRAM・RAM の指定があれば1検索 500 件、ほかは 100 件 | ユーザー回答。実測でエフォート＋VRAM 8GB が 100 件で 5 件、200 件で 7 件、500 件で 23 件 |
| 画像生成のジャンル | 欄を隠し、指定を外す。API は HF に聞かず空を返す | 画像モデルにテンプレートは無い |

## 変えないもの
- 指定なしのときの検索の結果と件数（結果に2項目増えるだけ）。
- ジャンル・無検閲・VRAM・RAM の動き。
- DL の仕組み。

## 影響（既知）
- HF の `gguf.total` は、下書き用の小さい GGUF を同梱するリポジトリで小さな値を返すことがある（例：`Qwen3.8-27B` の一部が 1.9B）。VRAM の絞り込みにこれらが残る。D-90 より前からの動き。
- 用途はタグ頼みなので、タグの無いモデルは出ない。

## 確かめ
- 本物の HF の件数（500 件に上げた後）：エフォート・思考はいずれも 50 件、エフォート＋日本語は 50 件、エフォート＋VRAM 8GB は 23 件。どの検索も約 1 秒
- `npm test`：439 件成功。残る `tests/music.test.ts` の1件は変更前も失敗する。一時フォルダの空きが 2GB 未満だと DL 系のテストが 507 で落ちるので、`TMPDIR` を実ディスクにして実行した
- `npm run typecheck`、`npm run build` が通る
- 画面（1280px, 960px, 390px）：絞り込み・思考の列・画像生成に切り替えたときの欄の消え方。960px 以下でページが横にはみ出さない
