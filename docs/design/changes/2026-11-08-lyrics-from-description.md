# 変更記録：曲の説明をもとに AI が歌詞を書く（2026-11-08）

> **3行で**：AI の下書きを ace-lm からチャットのモデルに替える ／ モデルは音楽の画面で選び、説明と長さを渡す ／ 歌詞が空のまま生成したときの作詞は ace-lm のまま

## 依頼と決定
| 項目 | 決定 | 根拠 |
|---|---|---|
| 歌詞を書くモデル | チャットのモデル（llama-server） | ユーザー回答。ace-lm の `inspire` は3回とも説明の内容を追えなかった（「むらかみいっきの曲、どこまでも突き進む曲…」→「与えられた命」の一般論、別の回はローマ字の同じ行の繰り返し） |
| モデルの選び方 | 音楽の画面でプリセットを選ぶ | ユーザー回答。アプリ全体の「今のプリセット」は無い |
| 長さ | 下書きに渡し、行数の上限を指示する | ユーザー回答 |
| 歌詞が空のまま生成 | 今のまま ace-lm | ユーザー回答 |
| 数値 | 1行 4 秒、32 秒未満は Verse と Chorus だけ、生成の上限 4,096 トークン、NFR-051 は 90 秒以内 | ユーザー回答 |

## 影響（既知）
- 下書きが GPU を使う。読み込み中のモデルと違うプリセットを選ぶと読み直しになる。
- 読み込んだモデルは下書きの後も残り、曲の生成を始めるときに止まる。

## 確かめ
- `npm test`、`npm run typecheck`、`npm run build`
- 画面（1280px, 960px）：代役の llama-server で、選択 → 下書き → 歌詞欄に入るまで。音楽モデルが無くても動く
- 実モデル（Qwen3.8 9B、`-ngl 20`、temperature 0.8）：60 秒×4回、180 秒×2回、60 秒の短い説明×1回、20 秒×1回の計 8 回。全部日本語で、説明の人名・店名・出来事が入った

## 残っていること
- 行数は守りきれない（60 秒で 12〜27 行、目安 15 行）。「かっこいい J-POP」など雰囲気の指示が歌詞に残ることがある。`[Famima]` のような説明にないタグが出ることがある（8 回中 2 回）。
- 実モデルでの確認は依頼文を直接 llama-server に送ったもの。アプリを通した実機の確認と、できた歌詞を実際に歌わせた確認はこれから。
